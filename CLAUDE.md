# ARM·BOX — веб-интерфейс манипуляторов

Фронт для двух роботов-манипуляторов на Dynamixel (6 серво: база, плечо, локоть, кисть, поворот схвата, схват). На каждой руке крутится свой backend (FastAPI, `main.py` + `ik.py`) и раздаётся эта же вебка. Backend в репозитории нет — только веб-часть и документация к нему.

Три страницы в `web/`:
- `index.html` + `present.js` — версия для показа: джойстики, схват, лампа, камера.
- `debug.html` + `app.js` — отладка: оси, программы точек, телеметрия, консоль API, настройки адресов.
- `game.html` + `game.js` + `ttt.js` — крестики-нолики двумя руками: игрок жмёт клетку, его рука рисует знак маркером.

## Команды

```bash
npm test          # node:test — кинематика (сверка с ik.py) и логика игры
npm run check     # синтаксис всех web/assets/*.js + тесты
npm run serve     # http://localhost:8080 — страницы; без железа открывать с ?demo
```

Зависимостей и сборки нет — не добавлять. Браузерная проверка вёрстки: Playwright (Python), страницы с `?demo` (демо-драйвер, руки не нужны).

## Устройство

| Файл | Что делает |
| --- | --- |
| `web/assets/kinematics.js` | Порт `ik.py` (см. `docs/ik.md`): `inverse`, `forward`, `isReachable`, `maxDistance`, `inWorkZone`, `WORK`. Экспорт `window.Kin` и `module.exports` |
| `web/assets/driver.js` | `RealDriver` (REST + WS), `DemoDriver` (симулятор), `Camera`, `request()` с понятными ошибками. Экспорт `window.Driver` |
| `web/assets/joystick.js` | Экранные джойстики и Gamepad API (`window.Joy`) |
| `web/assets/ttt.js` | Чистая логика игры: правила, минимакс, геометрия поле↔рука, план штрихов маркера. Экспорт `window.TTT` и `module.exports` |
| `web/assets/game.js` | UI игры: две руки, общая очередь движений, лампы, камера, вкладки «Настройка» и «Позиции» (ручная постановка руки над клетками) |
| `web/assets/present.css`, `style.css`, `game.css` | Одна палитра «алюминий + сигнальный оранжевый», светлая и тёмная тема |

Протокол backend, лампы и камеры — `docs/api.md`. Решения по игре — `docs/game.md`. Кинематика — `docs/ik.md`.

## Правила, которые нельзя нарушать

**Безопасность движения — главное.** Любая команда уходит на настоящее железо.
- Перед отправкой точки — проверка: `Kin.inWorkZone(x, z, angel)` (x ≥ 120 — упор в базу; угол 30…330 — упор и кабели; z ≤ 312). `ik.py` эти рамки НЕ проверяет — их держит фронт.
- Backend принимает только целые (`Driver.normalize`). В игре все движения — `POST /pos/set-paint` (`Driver.movePaint`, поле `paint_pov`), не `/pos/set`. Ответы WS приходят без id, строго по порядку (FIFO в `RealDriver.pending`).
- Следующую команду руке — только после завершения предыдущей (`move()` резолвится по окончании движения). В игре обе руки двигаются строго по очереди через `enqueue()` — они работают над одним листом.
- Шина серво полудуплексная: телеметрию опрашивать последовательно (`pos` → `temp` → `load`), не параллельно.
- Не отправлять запросы к реальным рукам (`curl` на `/api/motors/pos/set`, `/ws`) без явной просьбы пользователя. Для проверок — `?demo`.

**Кинематика.** `kinematics.js` обязан повторять `ik.py`. Меняется `ik.py` → обновить `docs/ik.md`, порт и опорные точки в `tests/kinematics.test.js` (позиции `start_position` и П-образной позы из документа). Тесты должны проходить до и после.

## Соглашения

- Чистый ES2020 в IIFE, без модулей и сборки; модули общаются через `window.*`. Файлы, нужные тестам (`kinematics.js`, `ttt.js`), дополнительно экспортируют `module.exports`.
- Интерфейс, комментарии, сообщения об ошибках — по-русски. Ошибки для человека: что случилось и что сделать («Рука ✕ не отвечает (192.168.0.10:8000)…»).
- Цвета только через CSS-переменные (`--alu`, `--plate`, `--ink`, `--signal`, …); каждое изменение вёрстки проверять в светлой и тёмной теме и на ширине 390 px.
- Шрифты: Unbounded — заголовки и цифры, Onest — интерфейс (`assets/fonts.css`, файлы шрифтов лежат на руке в `assets/fonts/`, в репозиторий не попали).
- `localStorage`: `armbox.settings` — пульт и отладка (и тема для всех страниц), `armbox.programs` — программы, `armbox.game` — игра. Чтение и запись всегда в `try/catch`.
- Названия полей API сохраняем как в backend, включая опечатку `angel` (угол базы).
