# ARM·BOX — веб-интерфейс манипуляторов

Фронт для двух роботов-манипуляторов на Dynamixel (6 серво: база, плечо, локоть, кисть, поворот схвата, схват). На каждой руке крутится свой backend (FastAPI, `main.py` + `ik.py`) и раздаётся эта же вебка. Backend в репозитории нет — только веб-часть и документация к нему.

Три страницы в `web/`:
- `index.html` + `present.js` — версия для показа: джойстики, схват, лампа, камера.
- `debug.html` + `app.js` — отладка: оси, программы точек, телеметрия, консоль API, настройки адресов.
- `game.html` + `game.js` + `ttt.js` — крестики-нолики двумя руками: игрок жмёт клетку, его рука берёт фигурку из своего лотка и ставит в клетку; после партии руки убирают фигурки в лотки.

## Команды

```bash
npm test          # node:test — кинематика (сверка с ik.py) и логика игры
npm run check     # синтаксис всех web/assets/*.js + тесты
npm run serve     # http://localhost:8080 — страницы; без железа открывать с ?demo
python3 scripts/server.py     # страницы + общая партия для нескольких ПК (комната), http://0.0.0.0:8080
sudo sh scripts/autostart.sh   # Linux: служба systemd armbox-web (server.py) на 8080 при загрузке (--remove — убрать)
```

Зависимостей и сборки нет — не добавлять. Браузерная проверка вёрстки: Playwright (Python), страницы с `?demo` (демо-драйвер, руки не нужны).

## Устройство

| Файл | Что делает |
| --- | --- |
| `web/assets/kinematics.js` | Порт `ik.py` (см. `docs/ik.md`): `inverse`, `forward`, `isReachable`, `maxDistance`, `inWorkZone`, `WORK`. Экспорт `window.Kin` и `module.exports` |
| `web/assets/driver.js` | `RealDriver` (REST + WS), `DemoDriver` (симулятор), `Camera`, `request()` с понятными ошибками. Экспорт `window.Driver`. `CAMERA = false` — камеры пока нет: всё с `data-camera` скрыто на всех страницах, опросов нет; появится — `true` |
| `web/assets/joystick.js` | Экранные джойстики и Gamepad API (`window.Joy`) |
| `web/assets/ttt.js` | Чистая логика игры: правила, минимакс, геометрия поле↔рука, цепочки «взять из гнезда → поставить в клетку» (и обратно — уборка), лотки. Экспорт `window.TTT` и `module.exports` |
| `web/assets/room.js` | Клиент комнаты `scripts/server.py`: долгий опрос, ведущий ПК, снимок, нажатия. Экспорт `window.Room`; без `server.py` — `null`, игра на одном ПК |
| `scripts/server.py` | Раздаёт `web/` и держит комнату (только stdlib). Общие настройки — `.data/room.json` |
| `web/assets/game.js` | UI игры: две руки, общая очередь движений, лотки (`armbox.game` → `tray`), лампы, камера, вкладки «Настройка» и «Позиции» (цепочки точек клеток и гнёзд со схватом в каждой точке) |
| `web/assets/present.css`, `style.css`, `game.css` | Одна палитра «алюминий + сигнальный оранжевый», светлая и тёмная тема |

Фигурки и гнёзда лотка для печати — `models/` (STL + генератор `pieces.py`, ему нужен `manifold3d`; STEP для КОМПАС — `pieces_step.py`, нужен `build123d`; к вебке отношения не имеет).

Протокол backend, лампы и камеры — `docs/api.md`. Решения по игре — `docs/game.md`. Кинематика — `docs/ik.md`.

## Правила, которые нельзя нарушать

**Безопасность движения — главное.** Любая команда уходит на настоящее железо.
- Перед отправкой точки — проверка: `Kin.inWorkZone(x, z, angel)` (x ≥ 120 — упор в базу; угол 30…330 — упор и кабели; z ≤ 312). `ik.py` эти рамки НЕ проверяет — их держит фронт.
- Backend принимает только целые (`Driver.normalize`). В игре все движения — `POST /pos/set` по REST (`driver.move(cmd, 'rest')`, `gripper_state` из `TTT.command` по настройке руки `gripTrue`); `/pos/set-paint` игра не использует. Ответы WS приходят без id, строго по порядку (FIFO в `RealDriver.pending`).
- Руками и лампами в игре командует только ведущий ПК (`hw()` в `game.js`); у остальных драйверов нет. Всё, что меняет партию, — через `act()`.
- Следующую команду руке — только после завершения предыдущей (`move()` резолвится по окончании движения). В игре обе руки двигаются строго по очереди через `enqueue()` — они работают над одним полем.
- Шина серво полудуплексная: телеметрию опрашивать последовательно (`pos` → `temp` → `load`), не параллельно. Пока `driver.moving` (движение в полёте и 400 мс после него), опрос пропускать: чтения во время движения делают его рваным.
- Не отправлять запросы к реальным рукам (`curl` на `/api/motors/pos/set`, `/ws`) без явной просьбы пользователя. Для проверок — `?demo`.

**Кинематика.** `kinematics.js` обязан повторять `ik.py`. Меняется `ik.py` → обновить `docs/ik.md`, порт и опорные точки в `tests/kinematics.test.js` (позиции `start_position` и П-образной позы из документа). Тесты должны проходить до и после.

## Соглашения

- Чистый ES2020 в IIFE, без модулей и сборки; модули общаются через `window.*`. Файлы, нужные тестам (`kinematics.js`, `ttt.js`), дополнительно экспортируют `module.exports`.
- Интерфейс, комментарии, сообщения об ошибках — по-русски. Ошибки для человека: что случилось и что сделать («Рука ✕ не отвечает (192.168.0.10:8000)…»).
- Цвета только через CSS-переменные (`--alu`, `--plate`, `--ink`, `--signal`, …); каждое изменение вёрстки проверять в светлой и тёмной теме и на ширине 390 px.
- Шрифты: Unbounded — заголовки и цифры, Onest — интерфейс (`assets/fonts.css`, файлы шрифтов лежат на руке в `assets/fonts/`, в репозиторий не попали).
- `localStorage`: `armbox.settings` — пульт и отладка (и тема для всех страниц), `armbox.programs` — программы, `armbox.game` — игра, `armbox.seat` — за кого играет этот ПК, `armbox.game.local` — свои настройки ПК до подмены общими из комнаты. Чтение и запись всегда в `try/catch`.
- Названия полей API сохраняем как в backend, включая опечатку `angel` (угол базы).
