# Обратная кинематика манипулятора: ik.py

Oct 19, 2026 · @Retmix

## Кратко

Файл `ik.py`, класс `InverseKinematics`: переводит координаты середины схвата в позиции серво ID1–ID4. Подключается в `main.py` без изменений `RobotARM`. Схват всегда смотрит вертикально вниз.

```python
ik = InverseKinematics()
pos = ik.calculate(x, z, angle)   # [pos1, pos2, pos3, pos4] или None
```

| Аргумент | Что это | Единицы |
| --- | --- | --- |
| `x` | расстояние от оси базы до середины схвата по горизонтали | мм |
| `z` | высота середины схвата над низом базы | мм |
| `angle` | поворот базы, 180° = позиция 2048 (центр) | градусы |

Возврат: список позиций в порядке ID (1, 2, 3, 4), диапазон 0…4095. `None` — точка недостижима, `RobotARM.move_arm` тогда бросает `ARMIKError`.

## Геометрия

Рука сводится к плоскому двухзвеннику (плечо + предплечье), поворачиваемому базой. Значения — из `arm_param.h`.

| Параметр | Значение, мм | Что это |
| --- | --- | --- |
| `BASE_HEIGHT` | 163.5 | высота оси плеча (ID2) над низом базы |
| `L1A`, `L1B` | 195.81, 67.36 | катеты Г-образного звена ID2–ID3 |
| `L1` | 207.07 | гипотенуза, которой заменено Г-звено |
| `L2` | 134.10 | звено ID3–ID4 |
| `L3` | 170.0 | от кисти (ID4) до середины схвата |
| `POSITION_OFFSET_DXL4` | 30 тиков | механическая поправка ID4 |

Максимальный вылет кисти от плеча: L1 + L2 = 341.17 мм, минимальный: L1 − L2 = 72.97 мм.

## Математика

Расчёт занимает один `sqrt` и два `atan2`; константы считаются один раз в `__init__`.

1. Переход к системе координат плеча: кисть на L3 выше схвата, начало — на оси ID2.

```latex
z' = z - \mathrm{BASE\_HEIGHT} + L_3
```

2. Локоть (ID3), конфигурация «локоть вверх». Если |c| > 1 или x ≤ 0 — возврат `None`.

```latex
c = \frac{x^2 + z'^2 - L_1^2 - L_2^2}{2 L_1 L_2}, \quad s = -\sqrt{1 - c^2}, \quad q_3 = \operatorname{atan2}(s, c)
```

3. Плечо (ID2), разность двух арктангенсов свёрнута в один:

```latex
k_1 = L_1 + L_2 c, \quad k_2 = L_2 s, \quad q_2 = \operatorname{atan2}(z' k_1 - x k_2,\; x k_1 + z' k_2)
```

4. Кисть (ID4) — схват строго вертикально, без `asin`:

```latex
q_4 = -(q_2 + q_3)
```

5. Перевод в позиции: pos = int(2048 × (q + смещение + калибровка) / π); к ID4 добавляется 30. Позиция вне 0…4095 → `None`.

Геометрические смещения (`ik_offsets`), α = atan(L1B / L1A) = 18.98°:

| Серво | Смещение | В градусах |
| --- | --- | --- |
| ID1 | 0 | 0 |
| ID2 | π/2 + α | 108.98 |
| ID3 | π/2 − α + π | 251.02 |
| ID4 | π/2 | 90.00 |

## Рабочие диапазоны

Кинематика работает при x от 120 до 341 мм, z от стола до 312 мм и angle 30…330°; максимальный x зависит от z.

| Параметр | Мин. | Макс. | Чем ограничено |
| --- | --- | --- | --- |
| x, мм | 120 | 341 (при z ≈ 0) | снизу — упор в базу; сверху — длина звеньев, `ik.max_distance(z)` |
| z, мм | ≈ 0 (стол) | 312 | снизу — касание стола, найти на руке (z = 20 проверено); выше 312 мм x ≥ 120 недоступен |
| angle, ° | 30 | 330 | расчёт допускает 0…359.9; 30…330 — запас до упора и кабелей. Не зависит от x и z |

## Проверка и опорные точки

На 10 784 точках рабочей зоны `ik.py` совпал с эталонным модулем `arm_kinematics.py` без расхождений. С прошивкой OpenCM — до 1 тика во всём диапазоне команды `g:`. Ошибка IK → позиции → FK не больше 0.8 мм — это квантование серво (1 тик = 0.088°). Точка x = 280, z = 20 проверена на руке.

| Поза | x, мм | z, мм | angle, ° | pos1 | pos2 | pos3 | pos4 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `start_position()` в `main.py` | 200 | 200 | 180 | 2048 | 2051 | 2094 | 1003 |
| П-образная (`MoveHome` в прошивке) | 134.1 | 200.57 | 180 | 2048 | 2263 | 1832 | 1054 |

В П-образной позе плечо вертикально, предплечье горизонтально (q3 = −90°). Если Present\_Position в этой позе отличается от таблицы — смещены нули серво, поправка через `set_calibration`.

Скрипт полной проверки — `ik_check.py` (карта зоны, сравнение с прошивкой, планировщик траектории).

## Отличия от старой версии и калибровка

При нулевой калибровке новый `ik.py` даёт те же позиции, что старый, там где старый работал.

| Было | Стало |
| --- | --- |
| q4 через `asin` — NaN / неверный угол низко у базы | q4 = −(q2 + q3), схват всегда вертикален |
| `acos`, `sin`, `cos`, `asin`, 2 × `atan2` | `sqrt` + 2 × `atan2` |
| Нет проверки 0…4095 | Позиция вне диапазона → `None` |
| `calc_ik_angular_offsets()` накапливает (`+=`) | Повторный вызов безопасен |
| Тестовый `print` при `import ik` | Под `if __name__ == "__main__"` |
| π/2 в `calibration_offsets` | π/2 в `ik_offsets`, `calibration_offsets` = 0 |
| — | Новые методы: `forward()`, `is_reachable()`, `max_distance()` |

**Калибровка** — только для ID2, ID3, ID4, в градусах, поверх геометрии:

- `set_calibration(dxl, angle)` — задать поправку (0 = без поправки)
- `add_calibration(dxl, angle)` — добавить к текущей
- `reset_calibration()` — сбросить поправки, геометрия не трогается

В старой версии `set_calibration(2, 0)` или `reset_calibration()` стирали π/2, и рука уходила на 90°. Теперь такие вызовы безопасны.

## Шпаргалка

```python
from ik import InverseKinematics
ik = InverseKinematics()

ik.calculate(280, 20, 180)        # [pos1, pos2, pos3, pos4] или None
ik.is_reachable(280, 20)          # True / False — проверить до отправки
ik.max_distance(100)              # 324.1 — макс. x на высоте z
ik.forward([2048, 2051, 2094, 1003])  # (x, z, angle) из Present_Position
ik.set_calibration(3, 1.5)        # поправка ID3 на +1.5°
```

- Перед `move_arm` с внешними координатами — `is_reachable()`, чтобы не ловить `ARMIKError`.
- `ik.py` не проверяет x ≥ 120, стол и угол 30…330° — эти рамки держать в вызывающем коде.
- Минимальный z найти на руке: опускать с шагом 5 мм до касания стола, прибавить запас.
- В прошивке OpenCM `MAX_DIST` = 400 — больше досягаемого; стоит поменять на 320.
